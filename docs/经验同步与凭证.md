# 经验同步与凭证

> 一句话：**仓库里不放任何 token，凭证永远是使用者自己的、只存在他自己机器上。**

## 哪些功能会用到 git 凭证

| 功能 | 入口 | 做什么 |
|---|---|---|
| **提交经验** | 控制台「经验」→「提交」 | 把本机经验导出一份 JSON 放进 `tools/experience-export/inbox/`，`git commit` 后 `git push` |
| **拉取经验** | 控制台「经验」→「拉取」 | `git pull` 后合并别人投稿的经验 |
| **发布版本** | `.github/workflows/package.yml` | GitHub Actions 构建并上传 Release；本地不再保存发布 token 脚本 |

提交与拉取都跑在**你部署的那台机器**上，用的是**你自己配的 git 凭证**。项目不代管、不内置、不收集任何人的 token。

## 部署后怎么配自己的凭证

三种任选一种，装完就能点「提交」。

### 方式一：GitHub CLI（推荐）

```powershell
winget install --id GitHub.cli
gh auth login            # 按提示走浏览器登录
gh auth setup-git        # 让 git 的 credential helper 接管
```

装完 `git push` 会自动带凭证，之后不用再管。

### 方式二：SSH key

```powershell
ssh-keygen -t ed25519 -C "you@example.com"     # 一路回车
cat ~\.ssh\id_ed25519.pub                      # 复制输出
# 粘到 GitHub → Settings → SSH and GPG keys → New SSH key
ssh -T git@github.com                          # 看到 "Hi <你>!" 就通了
git remote set-url origin git@github.com:<你>/<仓库>.git
```

### 方式三：Personal Access Token

GitHub → Settings → Developer settings → Personal access tokens → 生成（勾 `repo` 权限）。

```powershell
git config --local credential.helper store
git push        # 第一次会问用户名和密码，密码处粘贴 token
```

token 会被存在 `~\.git-credentials`（**本机文件，不在仓库里**）。想改用 `manager`：

```powershell
git config --global credential.helper manager
```

## 为什么不需要在项目里配置凭证

`tools/experience-export/` 和 git 本身都不存凭证：

- 经验提交调的是 `git push origin HEAD:main`，凭证由 **git 的 credential helper** 提供
- 发布脚本读 `GH_TOKEN` 环境变量，代码里只有 `x-access-token:{token_value}` 这样的占位符
- `.gitignore` 覆盖 `.env`、`*.key`、`configs/models.yaml`（含 API key）、`dist*/` 等

**扫描结论**：仓库里能搜到的 "`user:pass@`" 全部是测试用的假数据（`tests/test_har.py` 之类），没有任何真实凭证。

## 提交时报「被 .gitignore 忽略」怎么办

看到这种报错：

```
git add 失败：这些路径被 .gitignore 忽略了 —— tools/experience-export/inbox/xxx.json
```

不是你缺凭证。是 `.gitignore` 里有一条把投稿目录挡住了。检查并删掉类似规则：

```
tools/experience-export/inbox/*.json      ← 这条不能有
```

投稿目录必须能被提交，否则「提交经验」永远失败。

## 提交时报「还没有配置 GitHub 凭证」怎么办

说明这台机器确实没配。按上面三种方式任选一种装好即可，不需要改项目配置。
