# 打包与产物说明

当前仓库的 Windows 发布链只有一条主路径：

```text
pyproject.toml
    -> wheel
    -> build-python-runtime.ps1  (Python embeddable + 依赖 + 配置模板)
    -> build-native.ps1         (Compose Desktop + JRE + jpackage)
    -> dist-native\spiritscout-<版本>-native-win64.zip
```

旧的 WebView2、WinForms 壳、`desktop.json` 和单文件尾载荷流程已删除，不再作为
兼容产物维护。

## 产物

| 产物 | 用途 |
| --- | --- |
| `dist-native\spiritscout-<版本>-native-win64.zip` | 当前推荐的 Windows 原生桌面版，解压后双击 `SpiritScout.exe` |
| `dist-portable\spiritscout-<版本>-portable-win64.zip` | 纯 Python/后端便携包，给不需要原生窗口的兼容场景 |
| `dist\spiritscout-<版本>-py3-none-any.whl` | `pip install` 与服务端部署 |
| `dist\spiritscout-<版本>.tar.gz` | sdist，适合审源码或从源码构建 |

## 构建原生桌面版

前置条件：

- Windows 10/11 x64；
- Python 3.11+ 与 `build`；
- JDK 21，且包含 `jpackage.exe`；
- 首次构建可访问 Gradle/Maven 与 pypi（或设置镜像）。

先生成 wheel：

```powershell
python -m build --outdir dist SpiritScout
```

再运行：

```powershell
powershell -ExecutionPolicy Bypass -File SpiritScout\launcher\build-native.ps1
```

`build-native.ps1` 会自动调用 `build-python-runtime.ps1`。如果已有经过验证的运行时，
可以用 `-RuntimeDir <目录>` 复用；接口仍接受旧的 `-PortableDir` 别名，但新脚本只认
`py\python.exe` 与 `configs\system.yaml`。

常用参数：

```powershell
# 指定 wheel
powershell -ExecutionPolicy Bypass -File SpiritScout\launcher\build-native.ps1 `
  -Wheel D:\artifacts\spiritscout-1.3.0-py3-none-any.whl

# 指定运行时目录，跳过重复 pip 安装
powershell -ExecutionPolicy Bypass -File SpiritScout\launcher\build-native.ps1 `
  -RuntimeDir D:\build\spiritscout-python-runtime
```

## 验证

至少执行以下检查：

```powershell
# Kotlin 单元测试
$env:JAVA_HOME = 'C:\Program Files\Microsoft\jdk-21.0.12.101-hotspot'
.\SpiritScout\desktop\SpiritScoutCompose\gradlew.bat -p .\SpiritScout\desktop\SpiritScoutCompose test --rerun-tasks

# 确认 Python 运行时能导入
& .\SpiritScout\desktop\SpiritScoutCompose\build\python-runtime\py\python.exe `
  -c "import spiritscout; print(spiritscout.__version__)"

# 检查 zip 结构
Get-ChildItem dist-native -File
```

最终 zip 应从空目录解压启动一次，确认窗口标题、后端就绪、Skill 列表和关闭窗口后
Python 进程退出。SmartScreen 的“发布者未知”提示只有在发布者使用受信任的
Authenticode 证书签名后才会消失。
