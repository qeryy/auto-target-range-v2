### 为什么这是陷阱

`git commit` 提交的是**暂存区的全部内容**，不只是你刚 `add` 的。

所以如果直接：

```powershell
git add DesktopApp
git commit -m "..."
```

**那 11 条 web 改动会一起被提交**——违反「web 版不允许做任何修改」这条硬要求。
（虽然是历史遗留、不是我改的，但提交上去就等于承认改了。）

## 三、正确的提交流程

```powershell
# 1. 先清空暂存区（不动工作区文件，只是取消暂存）
git reset

# 2. 确认暂存区空了
git status --short
#    应该看到所有条目都变成 " M" 或 "??"（第二列有标记，第一列空）

# 3. 只加 DesktopApp 和根目录的 .gitignore
git add DesktopApp
git add .gitignore

# 4. 再次确认：暂存区里只有 DesktopApp 和 .gitignore
git status --short
#    不该出现任何 SpiritScout/ 开头的行

# 5. 提交
git commit -m "桌面版 2.0.0：纯 C# 原生实现"

# 6. 推送
git push
```

**第 4 步是关键的检查点**——如果 `git status --short` 里还有 `SpiritScout/`，
说明第 1 步没生效，停下来查。
