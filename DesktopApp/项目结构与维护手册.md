# 项目结构与维护手册

灵枢桌面版（`DesktopApp/`）的**改代码用**手册：目录职责、依赖方向、构建交付流程、
验证体系、UI 维护规范、以及踩过的坑。

面向的读者是「半年后打开这个目录要改点东西的人」，包括半年后的我自己。

## 四、构建与交付

### 编译

```powershell
# 本机 PowerShell 禁 Bypass/-File，脚本一律用 scriptblock 形式跑
powershell -NoProfile -Command "& ([scriptblock]::Create((Get-Content -Raw -Encoding UTF8 'build\build.ps1')))"
```

产物 `out\灵枢.exe`（.NET Framework 4.8 是 Win10/11 自带运行时，用户侧零依赖）。

要点，别改回「聪明」的写法：

- 只用系统 `csc.exe`（`Framework64\v4.0.30319`），**语言级别是 C# 5**：
  没有字符串插值 `$"..."`、没有 `?.`、没有 `using static`、没有元组。
- 版本号解析的正则**必须锚到 `public const`**（`build.ps1:49`）——只写
  `const string Version` 会匹配到注释里的示例文字，版本号被打成假值。
- 编译成败**只看 csc 退出码**，不看产物在不在（旧 exe 一直都在）。
- csc 写不进目标文件时报 `CS0016 拒绝访问`（杀软短暂锁），脚本只对 CS0016 重试 5 次。
  不能改成「先编到 `.new.exe` 再覆盖」——这个环境里新建 exe 会被拦。
- 脚本结尾**必须显式 `exit 0`**，否则 `$LASTEXITCODE` 残留会让调用方（verify_all、
  Python 子进程）拿到假的失败码。
- 嵌入资源两处都要给图标：`/win32icon:`（文件图标）和
  `/resource:assets\icon.ico,icon.ico`（运行时 `Theme.AppIcon()` 取的那份）。

### 技能库

`src/Resources/skills.json` 不是手写的，由 `build/export_skills.py` 从 web 版技能库生成。
改过技能内容要重新导出，否则桌面版看到的还是旧库（编译不会报错，只会打旧数据）。

### 验证 → 交付

```powershell
# 全量（结构 11 项 + e2e 141 断言 + 性能 6 项 + 配色 9 项），约 4.5 分钟
powershell -NoProfile -Command "& ([scriptblock]::Create((Get-Content -Raw -Encoding UTF8 'build\verify_all.ps1')))"
# 文档数字自动同步 + 校验（改完代码必跑，否则 README 里的行数/大小是旧的）
powershell -NoProfile -Command "& ([scriptblock]::Create((Get-Content -Raw -Encoding UTF8 'build\doc_sync.ps1')))"
powershell -NoProfile -Command "& ([scriptblock]::Create((Get-Content -Raw -Encoding UTF8 'build\doc_check.ps1')))"
```

发版顺序固定：**build → verify_all → 截图重拍（若界面变了）→ doc_sync/doc_check →
README + 发布说明 → 交付 `out/灵枢.exe`**。

## 六、UI 维护规范

### 6.1 DPI 与分辨率

- 进程是**系统 DPI aware**（`build/app.manifest` PerMonitorV2 声明），
  比例由 `Theme.InitScale()` 从屏幕 DC 读 `LOGPIXELSX` 得到 `Theme.UiScale`
  （`Theme.cs:516`）。**不要指望 WinForms 的 AutoScale**：单文件 exe 没有
  app.config，`DeviceDpi` 实测恒 96，所以所有 Form 都是 `AutoScaleMode.None`。
- 代码里写的尺寸/字号一律是**设计像素**（按 100% 屏设计）。两条换算通道：
  - 布局常量：`Theme.K(int)` / `Theme.Kf(float)`（自绘控件内部用）；
  - 整棵控件树：`Theme.ScaleTree(control)`（`Theme.cs:533`，用
    `ConditionalWeakTable` 去重，同一棵树只缩一次）。
- 布局回调里判断该用哪套单位：`Theme.UnitOf(c)`，并且遇到
  `Theme.IsScaling == true` 直接 return（缩放过程中 `ClientSizeChanged` 会同步触发，
  此刻按物理像素插一手就会被再乘一次）。
- **子窗口一律走 `Theme.ApplyWin11(this)`**（`Theme.cs:174`），它在一次调用里做了：
  1. `form.Icon = Theme.AppIcon()`；
  2. DWM 圆角 + 原生滚动条压暗；
  3. `Load` 时 `ScaleTree(form)` → DPI 缩放（实测 `Form.Scale()` 连窗口自己的
     ClientSize/MinimumSize 一起缩，所以对话框写设计尺寸就够）；
  4. `Load` 时 `FitWindow(form)` → 窗口超出所在屏工作区时夹紧，
     `MinimumSize` 一起夹，夹小后开 `AutoScroll` 让客户区外的控件还能滚到；
  5. `Shown` 时 `EnsureOnScreen(form)` → 整窗拉回工作区内（CenterParent
     在多屏/父窗靠边时会算出负坐标，标题栏跑到屏外就没法拖）。
  **新加 Form 只要不调它，就等于没有图标、没有圆角、没有 DPI 缩放、没有小屏兜底。**
- 主窗体 `MainForm.ApplyAdaptiveSize()`（`MainForm.cs:704`）单独按工作区算初始尺寸和
  最小尺寸，另有 `WindowStateStore` 负责记住/恢复位置并做屏外兜底。

150% 屏（本机）实测：`SkillDialog` 760x620 设计 → 1140x930 物理；伪造 1366x728
小屏时夹到 1140x648 且 `AutoScroll=True`。夹紧路径在本机不会触发，靠
`layout_check.ps1` 的小屏两档跑，别只在大屏上看一眼就交。

### 6.1.1 字号：**一个常量，不是 92 个文件**

全站字体只有一个出口：`Theme.F(pt)` → `Fpx()` →
`new Font(family, Kf((pt + FontBump) * 96/72), style, GraphicsUnit.Pixel)`。
`Theme.FontBump`（`Theme.cs`）是**全局字号增量**，第九轮按用户要求设成 `2F`
（整体放大两个字号）；要调回去或再加，只改这一个常量，别逐页翻字号。

- 字号是**像素单位**且已经乘过 `UiScale`，所以它跟 DPI 走；控件树再靠
  `ScaleTree` 缩一次字面尺寸——两套通道叠加，这就是「字号变大后先坏在自绘几何和
  对话框」的原因。
- 各档实测（100% 屏，含 FontBump）：正文 16px、小字 14px、微字 13.3px、
  标题 24px、区块名 14px、指标 26.7px、等宽 15.3px；150% 屏再乘 1.5。
- 徽章这类**跟文字比例走**的自绘尺寸要跟着调（`ChatBubble.SealW` 25→32，
  保持「徽章 ≈ 正文两倍见方」）。
- 改完必须跑 `fit_check.ps1`（第五节），它专门量文字和装它的盒子。

### 6.2 自绘控件铺底：**必须画在 OnPaint 里**

**`Button`/`ButtonBase` 派生的控件（含 `CheckBox`），`OnPaintBackground` 实测根本不会被调用**，
即使加了 `UserPaint | AllPaintingInWmPaint | OptimizedDoubleBuffer`。

后果：双缓冲画布的内容是「上一次借用这块缓冲的那个控件」的像素。同尺寸的兄弟控件
（侧栏导航项、通知页四个开关）之间反复回收缓冲，旧文字就被压印进来 —— 这就是
「文字重叠/残影」。`Invalidate(true)` 治不了，因为背景这一步压根没执行。

所以：

- 继承 `Button`/`CheckBox` 的自绘控件，**OnPaint 第一行就铺底**：
  侧栏类铺实色（`NavItem.cs:100`、`SessionItem.cs:82`），浮在软面上的铺
  `AmbientPanel.PaintBase(this, g)`（`FlatButton.cs:109`、`ModeCard.cs:77`、`Switch.cs:116`）。
- `OnPaintBackground` 可以留着当非缓冲通路的兜底，但注释里要写清它不会被调用。
- `Panel`/`Control` 派生的（`SidePanel`、`SectionCard`、`Card`、`HeroTitle`、`Sparkline`）
  不受影响：透明子控件模拟透明时采的就是它们的 `OnPaintBackground`，**那几个必须留在
  OnPaintBackground**，别顺手「统一风格」搬过去。

现有自绘控件清单（`src/Ui/Widgets/`）：

| 控件 | 基类 | 铺底位置 |
|---|---|---|
| `FlatButton` / `ModeCard` / `NavItem` / `SessionItem` | Button | OnPaint |
| `Switch` | CheckBox | OnPaint |
| `SidePanel` / `BrandPanel` / `ChatBubble` | Panel | OnPaintBackground |
| `SectionCard` / `MetricTile` / `Card` | Card(Panel) | OnPaintBackground |
| `HeroTitle` / `Sparkline` / `DarkSelect` | Control | OnPaintBackground / OnPaint |
| `DataTable` | DataGridView | 主题在控件内部自绘 |
| `DarkTabs` | TabControl | DrawMode=OwnerDrawFixed |
| `DarkTextBox` | TextBox | 深色边框靠 WndProc |

### 6.3 颜色与「软面」

- 页面里**不许写死 `Color.FromArgb`**，一律取 `Theme.XXX`；配色对齐 SaltUI 暗色
  （`Theme.cs:324` 起有逐值对照）。
- 色阶必须逐级变亮：`Bg < Surface < SurfaceAlt`。卡片比页面背景暗就是「凹进去」，
  这个错犯过一次（2026-11-19）。
- 自绘子控件不要铺自己的硬底色，用 `AmbientPanel.PaintBase(c, g)` 采样所在软面
  （卡面含色晕），否则圆角外会露出一圈不同颜色的方框。
- **软卡自己铺底要用 `PaintAncestorBase`，不是 `PaintBase`**：后者的循环从控件本身
  起步，`Card` 传进去第一步就命中自己 → `PaintSurface → PaintBase → PaintSurface`
  无限递归（258 轮踩过）。
- **卡面必须全不透明**：`RenderSurface` 第一句铺祖先底色，然后才画投影。
  透明画布上的半透明投影环，控件每重绘一次就再合成一遍，贴卡边越刷越深
  （单次 17%，实测刷到 43%，就是「框旁边有黑边」）。
- **投影的环数 = 卡面实际留白 `pad / 2`，不是 `ShadowSpread`**：留白只有 7px 却按
  13px 扩散，超出控件边界被硬裁一刀，留下的正好是最深那几环，看着就是一条黑线。
  别的调用点（`ModeCard`）同理，传自己真实的 pad。
- 焦点圈半径要夹：`Math.Min(K(Radius), focusRect.Height / 2)`，否则胶囊按钮上
  会画出月牙形蓝斑。

### 6.4 图标与嵌入资源

`assets/icon.ico`（7 档尺寸，16–256，32bpp）。运行时取法：`Theme.AppIcon()`
（`Theme.cs:205`）→ 嵌入资源 `icon.ico` → `Icon.ExtractAssociatedIcon(exe)` →
`SystemIcons.Application`。标题栏/任务栏/托盘气泡共用同一个实例，**谁都不许 Dispose 它**。

「exe 文件图标对、窗口图标是通用图标」是同一份 ico 只用了一次造成的：
`/win32icon` 只写进 PE 的资源表，运行时拿不到，必须再 `/resource:` 嵌一遍。
「关于 → 运行自检 → 程序图标」这一项就是查这个（`SelfCheck.CheckIcon()`）。

## 八、排查与探针

### 程序自带的开关（`src/Ui/Program.cs:162-176`）

```
灵枢.exe --page notify                 直接打开某页（id 见 PageRegistry）
灵枢.exe --page session:<会话id>        直接打开某个会话（做快捷方式用）
灵枢.exe --screenshot <png>            渲染完画成 PNG 再退出
灵枢.exe --dump-ui <txt>               把整棵控件树的类型/边界/底色/文字写出来再退出
灵枢.exe --no-focus                    显示但不激活、不抢前台（后台跑检查必带）
```

`--dump-ui` 是判「重叠是布局问题还是绘制问题」的关键：边界不重叠 + 屏幕上压字
= 绘制问题（见 6.2），别再改布局。

### 日志

`<数据目录>/logs/app-YYYYMMDD.log`。数据目录解析顺序（`src/Core/AppPaths.cs:14`）：
`%APPDATA%\SpiritScout` → `<exe目录>\data`（受限账户/便携）→ `%TEMP%\SpiritScout`，
实际落在哪一处会显示在「设置 → 数据位置」，`RootKind` 是它的名字。

注意：**在智能体的受限 shell 里跑测试 exe，AppData 候选会被拒写**
（`UnauthorizedAccessException`），于是数据落到 exe 旁边的 `data\` ——
`out/data/`、`build/_probe/data/` 这些残留就是这么来的，不是交付物，也别据此判断
用户那边的路径（用户双击运行正常落在 `%APPDATA%\SpiritScout`）。

### 编译期探针（不进交付）

`build/_probe/` 是历史上放一次性探针的目录，**现在已清空**：
`scaleprobe.cs`（验 `Form.Scale()` 缩不缩窗口自己的 ClientSize，结论：缩）和
`fitprobe.cs`（伪造小屏工作区验 `FitWindow`、`--selfcheck` 打 11 项离线自检）
的结论都写进了上面的规范，探针本身删了。

排版这块的**后继者是常驻检查**，不再是临时探针：`build/tests/LayoutFit.cs`
+ `build/fit_check.ps1`（第五节）。它和 e2e 一样用系统 csc 把全部源码
（排除 `src/Ui/Program.cs`）连同测试自己的 `Main` 编成 exe，
所以能调 `Theme` 的 `internal` 成员；带 `-Shots <目录>` 会把对话框画成 PNG。

编译探针/测试 exe 的命令和正式编译一样是系统 csc，只是 `-target:exe`、去掉
Program.cs、加上测试自己的 Main，并且要带 `-win32manifest:build\app.manifest`
（否则进程不是 DPI aware，`UiScale` 会算成 1，测出来的缩放全是假的）。

**注意 `build/_probe/data/` 这类残留**：受限 shell 里跑测试 exe 时 AppData 被拒写，
数据落到 exe 旁边的 `data\`（见上面「日志」一节），不是交付物，定期清掉。

## 九、踩过的坑（按「再犯一次的成本」排序）

1. **Button/CheckBox 派生的自绘控件把铺底写在 OnPaintBackground** → 残影/压字。
   见 6.2。这是最贵的一次：前一轮「已修复」的结论是错的，因为验证只看了
   截图没换页面顺序，而缺陷只在缓冲被同尺寸控件回收时出现。
2. **锁屏下 UIA 拿到空矩形 → 检查假绿**。跑界面检查时用户可能锁屏，
   控件边界全空但断言「没有越界」照样通过。看到「全绿但界面没变」先怀疑这个。
3. **csc 语言级别是 C# 5**。用了插值/`?.`/元组会编译失败，而且报错信息在 GBK 输出里
   容易看漏。
4. **`$LASTEXITCODE` 靠管道最后一环**。`& $csc … | ForEach-Object` 之后判断退出码不可靠；
   先取原始输出和退出码，再逐行打印。
5. **编译失败时旧 exe 还在**。判成败只看退出码，否则「[+] 产物：1876 KB」会对着
   一个没变过的旧文件打出来。
6. **版本号正则没锚 `public const`** → 匹配到注释里的示例值，静默打错版本。
7. **`/win32icon` 与 `/resource` 只做其一** → 文件图标对、窗口/任务栏是通用图标。
8. **doc_sync/doc_check 读源码不带 `-Encoding UTF8`** → PS5 按 GBK 读，中文注释乱码、
   行数少算，文档数字永远对不上。
9. **PowerShell 执行限制**：本机禁 `-ExecutionPolicy Bypass -File` 跑无签名脚本，
   一律 `-Command "& ([scriptblock]::Create((Get-Content -Raw -Encoding UTF8 '…')))"`。
   `wmic` 已删，`tasklist` 输出是 GBK。
10. **GUI 检查一律 `--no-focus` 后台跑**，不许弹前台、不许抢用户焦点；
    需要起窗口的检查也按这条来。
11. **`DrawToBitmap` 画出来的非客户区是浅色的**（WM_PRINT 不还原 DWM 深色标题栏），
    别拿它判断标题栏配色，要用 Windows Graphics Capture 实抓。
12. **改完只更新一份文档**。9 份文档里有同一批数字，跑 `doc_sync.ps1` 而不是手改。
13. **提交**：暂存区里可能已经有 web 版（`SpiritScout/`）的改动，
    照 `提交前必读.md` 的流程走，别 `git add -A`。
14. **投影画得比留白宽，又留在透明画布上** → 卡边一条近黑带，且越刷越深。
    见 6.3。这类「合成层」的问题肉眼在单页截图上看不出来，要沿卡边采样像素亮度
    （底色 23、黑边 5 那种量级才说明问题），改完再采样一次。
