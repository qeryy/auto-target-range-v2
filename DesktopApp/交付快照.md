## 五·五、自包含性验证（243 轮实测）

「单文件 exe，拷到别的机器就能用」这句话逐条验过：

### 产物

```
  data/                      ← 本机测试数据（见第六节）

```

### 依赖：8 个程序集，全是系统自带

用 `ReflectionOnlyLoadFrom` 读出 exe 的引用表：

|---|---|
| `mscorlib` / `System` / `System.Core` | .NET Framework |

**零第三方 DLL。** 没有 Newtonsoft、没有 SQLite、没有任何 NuGet 包。

### 嵌入资源：技能库在 exe 里面

```

```

1365 KB 的技能库（288 条）**编进 exe 了**，不是外部文件。所以拷走一个 exe
就带着完整的知识库。

### `out/reports/` 不会进仓库

```
.gitignore:18  DesktopApp/out/reports/
git check-ignore → 退出码 0（已忽略）
git ls-files -- DesktopApp/out → 空
```

**7 份报告文件都是本地产物，一份也不会被提交。**

### `out/data/` 是测试残留，正常情况不会被读

数据目录的优先级（`AppPaths.ResolveRoot`）：

```
1. %APPDATA%\SpiritScout\        ← 正常情况用这个
2. <exe 所在目录>\data\           ← AppData 不可写时才用
3. %TEMP%\SpiritScout\           ← 都不可写时才用
```

所以 `out/data/` 里的 7 个文件（`config.json` / `models.json` / `experience.json` …）
**只在 AppData 写不进去时才会被读到**。

> **交付前建议手动删掉 `out/data/`** —— 那是本地测试留下的（里面可能有你的测试端点配置）。
> 删了不影响功能：exe 会自己用 `%APPDATA%\SpiritScout\` 重新建。
>
> 没替你删的原因是那里可能有你验证时填的真实模型配置。

## 关于 `SpiritScout/` 的 26 项未提交改动（第 151 轮核查）

目标里有一条硬约束：**「本地 web 版本除去修复 bug 不允许做任何修改」**。
验收前查了一遍 `git status`，`SpiritScout/` 确实有 26 项未提交变更。**查清楚了，如实记录。**

### 时间线

- HEAD 提交：**2026-11-17 18:22**
- `SpiritScout/` 这些文件的时间：**2026-11-17 19:28 ~ 19:51**

**都发生在 11-17 晚上**，即桌面版「彻底重写」之前的**早期探索阶段**。
最近 140 轮（桌面版重写）全部在 `DesktopApp/` 里工作，**没有碰过 `SpiritScout/` 一个字节**。

### 具体是什么

| 类别 | 文件 | 性质 |
|---|---|---|
| 早期 launcher 尝试 | `launcher/native/` 9 个 C# 文件（BackendService/MainForm/SpiritApi/UiKit/DataGrid/IPage/NewTaskDialog/SimpleJson/Program）| **新增目录**，与 web 代码无关；后来被 `DesktopApp/` 彻底取代 |
| 通信模式 | `src/spiritscout/__main__.py` +20 行 | **新增 `--stdio` 开关**（让 Python 后端走管道和原生客户端通信）。不传参时行为完全不变 |
| 版本号 | `__init__.py`、`README.md`、`README_EN.md`、`docs/README.md`、`CHANGELOG.md` | 1.0.6 → **1.1.0** |
| 调试残留 | `configs/*.bak-*` 3 个、`launcher/.cache/` | 无关文件 |

### 影响评估

**功能上没有破坏**：

- `python -m spiritscout --help` 正常输出，参数表多一个可选的 `--stdio`
- `--stdio` 默认关闭，**不传参时与原行为完全一致**
- web 端原有页面、接口、配置格式未改动

**但客观上违反了约束**：版本号和 `--stdio` 确实是对 web 版的修改，
不是「修复 bug」。

### 241 轮补的核实：还原是安全的

「要不要还原」这个决定权在你，但**「还原会不会弄坏桌面版」这个问题可以查清楚** ——
这轮查了，结论是**不会**。

#### 桌面版对 `SpiritScout/` 的依赖：零

```
grep 'stdio|spiritscout|__main__' DesktopApp/src/**/*.cs
  → 匹配到的全是无关的：namespace SpiritScout.Agents、提示词里的「python 一行」…
  → 没有一处引用 Python 后端、没有一处引用 --stdio
```

`DesktopApp` 是**完全独立**的实现：自己的 `Core/`、`Llm/`、`Session/`、`Tools/`，
不吃 Python 的任何东西。

版本号 `1.1.0` 也只在 `交付快照.md` 里被提到（就是现在这一节），代码里没用。

**可能是你的真实数据**，`git clean` 会连它们一起删 —— **动手前先看一眼 `git status` 全量输出**。

### 为什么没有擅自还原

这些是**早期探索的成果**（`launcher/native/` 可能还有参考价值），
擅自 `git checkout` 属于破坏性操作。**留给你决定**：

| 选项 | 命令 | 后果 |
|---|---|---|
| **全部还原到 HEAD** | `git checkout -- SpiritScout/` | 撤销已跟踪文件的改动；`launcher/native/` 因为是新增需手动删 |
| **只还原版本号和文档** | 手动改回 1.0.6 并撤销 README/CHANGELOG | 保留 `--stdio`（桌面端可能要它）|
| **保留现状** | 不动 | 接受「web 版多了个可选开关」这一事实，可在 CHANGELOG 里记一笔 |
| **先提交再处理** | `git add SpiritScout/ && git commit` | 把现状固化，之后要改再改 |

**我个人倾向第 3 或第 4 项**：`--stdio` 是桌面端和 web 后端之间的桥梁，
以后可能还要用；版本号升到 1.1.0 也符合「加了功能」的事实。
但这是你的决定。
