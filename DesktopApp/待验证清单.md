### 1. 会话页 →「拓扑」标签

> **先纠正一个说法**：桌面版**没有「编排模式」开关**。
> `SessionView.cs:634` 每个会话都走 `Orchestrator`，`DelegateTool` 是**常驻注册**的
> （`tools.Register(new DelegateTool(...))`）。**要不要派子任务由模型自己决定。**
> 所以「开编排模式跑一次」这种说法不存在，得换别的办法触发。

**办法一（最省事）**：问一个明显需要分工的任务，比如

```
目标是 example.com，先做信息收集，再针对开放端口逐个看。
```

主 Agent 有可能（不保证）调 `delegate` 把侦察和端口测试分给两个方向 agent。

**办法二（一定能触发）**：手工往会话文件里加一条 delegate 消息。

1. 建一个任务，随便发一句话，让它落一个会话文件
2. 关掉程序，打开 `%APPDATA%\SpiritScout\sessions\<会话id>.json`
3. 在 `messages` 数组里加一条：

```json
{
  "Id": 999,
  "SessionId": "<同一个会话id>",

  "Name": "delegate",
  "Content": "[delegate] 密码分析：RSA 小模数分解拿到明文",

}
```

4. 重开程序，打开那个会话 → 「拓扑」标签

第三条主题不同（不该被归进同一组）。

> **字段名是 PascalCase**（`Insight` / `Mode` / `Tags`），不是小写 —— 因为

## P2 · 出错路径（难触发，但影响大）

这几条**平时看不见**，出问题时才走到。恰恰最不容易被发现是坏的。

### 8. 崩溃提示

> **这一条我第一版写错了，必须说清楚。**
>
> 原来写的是「把 `config.json` 改成非法 JSON 再重启，看崩溃框」——
> **验不出来**。`ConfigManager.Load()` 走的是
> `JsonStore.Read<AppConfig>(ConfigFile, null) ?? new AppConfig()`：
> 坏 JSON 会被捕获、**改名成 `.broken-<时间戳>` 留证**、然后回退默认配置。
> 整个过程**不抛异常**，一个框都不会弹。你只会看到「配置被重置了」。

#### 6a. 启动失败提示（不用改代码）

**怎么验**：在数据目录里建一个**名叫 `config.json` 的目录**（不是文件）。

```
%APPDATA%\SpiritScout\config.json\      ← 建这个目录
```

这样 `File.Exists("config.json")` 为假 → `EnsureInitialized()` 会去 `Save()` →
`JsonStore.Write` 写盘失败（目标是目录）→ 抛异常 → 被 `Program.Main` 的 catch 接住。

  看什么   期望  
 --- --- 
  弹出框   「**启动失败：数据目录用不了**」+【版本】【错误】【目录】【怎么办】  
  【怎么办】   有「关掉其它灵枢窗口」「放到有写权限的目录」这类**可操作**建议  

验完把那个目录删掉。

#### 6b. 通用崩溃提示（要临时改代码）

`ReportCrash` 只在**未处理异常**时触发。现在绝大部分异步路径都包了 try/catch 或
`UiSafety.Fire`，**没有一条正常操作能稳定触发它** —— 这本身是好事。

要验它，只能在某个按钮处理器里临时插一行：

```csharp
// 比如 AboutPage 的「复制报告」按钮里，第一行加：
throw new InvalidOperationException("崩溃提示验证");
```

重编、点那个按钮。

  看什么   期望  
 --- --- 
  弹出框   【位置】界面线程异常 / 【版本】**2.0.0**（不是 `2.0.0.0`）/ 【错误】/ 【日志】/ 【下一步】五段  
  日志目录   能打开，当天那份 log 里有这次的堆栈  

**验完一定把那行删掉再重编** —— 留着就是线上崩溃点。

### 9. 自检第 10 项「损坏文件备份」

**怎么验**：在数据目录丢一个空文件 `x.json.broken-20260101120000`，然后跑自检。

  看什么   期望  
 --- --- 
  自检输出   「**10 项**」，其中「损坏文件备份」是 `!`（Warn），列出那个文件名  
  没有坏文件时   该项 `✓`「没有（文件都读得出来）」  
  **第 1 项「.NET 运行时」**   `✓` 显示当前版本（如「.NET Framework 4.8（Release 528372）」）；低于 4.8 会变 `!`  

### 10. 密钥库解不开

**怎么验**：把 `%APPDATA%\SpiritScout\secrets.dat` 拷一份到别的 Windows 用户下跑
（或直接改几个字节破坏它）。

  看什么   期望  
 --- --- 
  日志   「密钥库解不开，已降级为空：… · 原件已备份为 secrets.dat.unreadable-…」  
  目录里   多出 `secrets.dat.unreadable-<时间戳>`，**原件还在**  
  之后保存一次配置   `secrets.dat.unreadable-*` **不会被覆盖**  

> 这条修的是数据丢失：原来解不开 → 空表 → 用户改任一供应商 →
> 写回只写那一条 → 其余密钥永久丢失。
