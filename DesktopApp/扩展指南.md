# 怎么加功能、怎么删功能

## 改动量速查

下表是**实测**的（不是估计）——写脚本扫了所有引用点：

| 要加/删什么 | 新建文件 | 要改的行 | 涉及文件 |
|---|---|---|---|
| **一个页面** | 1 个 `XxxPage.cs` | 5 处（注册 + 图标 + smoke + clip/layout/overflow 三份清单） | `Program.cs`、`IPage.cs`、`build/smoke.ps1`、`build/*_check.ps1` |
| **一个工具** | 1 个 `XxxTool.cs` | 1 行（注册）+ 可选 1 行（agent 白名单） | `ITool.cs`、`AgentProfile.cs` |
| **一个 agent** | — | 约 10 行（一个对象） | `AgentProfile.cs` |
| **一个会话标签** | — | 约 60 行（一个 `BuildXxx`）+ 4 行（挂上去） | `SessionTabs.cs`、`SessionView.cs` |
| **一个自绘控件** | 1 个 `Xxx.cs` | 0（用它的地方 `new` 一下） | — |
| **一个配置项** | — | 3 处 | `Storage.cs`、`SettingsPage.cs`（控件 + 保存）、使用方 |
| **一条技能** | — | 0（界面上填） | — |
| **一个 MCP 服务器** | — | 0（界面上填） | — |

**删的时候同样简单**。但要分清两件事：

#### 运行时：漏改不会崩，会静默退化

- 删工具后忘了从 agent 白名单里去掉名字 → `Find(name)` 返回 null，**直接跳过**，
  那个 agent 静默少一个工具
- 删页面后忘了摘图标映射 → `PageIcons.Get()` 返回空串，按钮只是没有图标

**这是刻意的设计**：宁可退化成功能缺失，也不要让程序崩在用户面前。

#### 但交付前会被拦住（这点以前没写清楚）

静默退化对**用户**是好事，对**开发者**是陷阱 —— 漏了不会有任何提示，
你自己发现不了。

所以现在有 `build/tool_parity.ps1` 拦这两种：

```
[FAIL] 白名单里有、但没注册的工具: note
       → 这些名字在运行时会被静默跳过，对应 agent 少了能力

[FAIL] 这些页面没有图标（侧栏会缺一个符号）: probepage
       → 在 src/Ui/IPage.cs 的 PageIcons.Map 里补一行
```

> **「运行时能退化」和「开发时能发现」是两件不同的事。**
> 这版两个都做到了：用户那边不崩，开发这边会红。
>
> 早先只做到前半句 —— 那份文档读起来像「漏了也没关系」，其实是
> 「漏了程序能活，但检查会拦住你」。

跑一次 `tool_parity` 就知道所有清单有没有对齐（它现在有 6 条不变量）。

## 总览

> 这份文档证明「可维护、可扩展」不是口号——每一步都能实际跑一遍验证。

灵枢桌面版把每种可扩展点都设计成**一个文件 + 一行注册**。下面四种是你会用到的。

## 加一个页面

**改四个地方**（原来这里写「两个地方」，但下面列了三步、而实际要四步 —— 见文末实测）：

1. 新建 `src/Ui/Pages/YourPage.cs`：

```csharp
public sealed class YourPage : IPage
{
    public string Id { get { return "yourpage"; } }          // 稳定标识
    public string Title { get { return "你的页面"; } }        // 侧栏显示名
    public PageGroup Group { get { return PageGroup.Main; } } // 分组

    public Control CreateView()                              // 只调一次
    {
        var root = new Panel { Dock = DockStyle.Fill, BackColor = Theme.Bg };
        // …建你的控件…
        return root;
    }

    public async Task RefreshAsync()                         // 每次进入/点刷新
    {
        // …拉数据、填表格…
        await Task.CompletedTask;
    }
}
```

2. 在 `src/Ui/Program.cs` 的 `RegisterPages()` 里加一行：

```csharp
PageRegistry.Register(new Pages.YourPage());
```

3. 在 `src/Ui/IPage.cs` 的 `PageIcons.Map` 里加一行图标：

```csharp
{ "yourpage", "\u25C9" },   // ◉ 你的页面
```

`PageIcons.Get` 查不到就返回空串 —— 侧栏那一项**只是没有图标**，程序照跑。
所以**不加也能编过**，只是和其余项摆在一起显得缺了一块。

**但 `build/tool_parity.ps1` 会拦住它**：

```
注册页面: 14 个 · 有图标: 13 个
[FAIL] 这些页面没有图标（侧栏会缺一个符号）: yourpage
       → 在 src/Ui/IPage.cs 的 PageIcons.Map 里补一行
```

**这条检查是第 146 轮加页面时漏掉图标之后补上的。**

4. 在 `build/smoke.ps1` 的 `$pages` 数组里加一条：

```powershell
@{ key = 'yourpage'; name = '你的页面'; expect = @('你的页面', '关键文字1', '关键文字2') },
```

`key` 要等于页面的 `Id`；`name` 是侧栏显示名；`expect` 是这一页上**必然出现**的几段
文字（冒烟检查会读控件树，确认这几段都在）。

**这一步漏了 `check_all` 会红：**

```
smoke 覆盖 13 页 · PageRegistry 注册 14 页
[FAIL] 这些页面不在 smoke.ps1 里（加了页面但没加冒烟项）: yourpage
       → 在 build/smoke.ps1 的 pages 数组里补一条（key/name/expect）
```

**主窗口不用动**——侧栏是从 `PageRegistry` 自动生成的。

**验证过三次**：

| 轮次 | 怎么验的 | 结论 |
|---|---|---|
| 146 | 真加一个临时页面，只写文件 + 注册 | 能出来，但**图标忘了侧栏少一个符号** → 补了 `tool_parity` 检查 |
| 225 | **照着这份指南重新走一遍** | **指南漏了第 4 步**（smoke）→ 补上了 |
| 225 | 补完再验一次 | 四步齐了，`tool_parity` 全绿 |

第 225 轮的做法：真建一个 `ProbePage.cs`、注册、跑 `tool_parity`，看它报什么：

```
注册页面: 14 个 · 有图标: 13 个
[FAIL] 这些页面没有图标（侧栏会缺一个符号）: probepage              ← 指南里写了
smoke 覆盖 13 页 · PageRegistry 注册 14 页
[FAIL] 这些页面不在 smoke.ps1 里（加了页面但没加冒烟项）: probepage  ← 指南里没写
```

**第二个 FAIL 是意外收获** —— 三步全做完，`tool_parity` 还在报错。
补了图标它照样报，因为 smoke 那条从来没被写进这份指南。

> **写「怎么做」的文档，最好的验证方式是照着它做一遍。**
> 凭记忆列步骤，漏掉的那步自己永远发现不了 —— 因为写的人心里有它，纸上没有。

## 加一个工具

**改两个地方（+ 一个可选的第三步）**：

1. 新建 `src/Tools/YourTool.cs`，实现 `ITool`：

```csharp
public sealed class YourTool : ITool
{
    public string Name { get { return "your_tool"; } }
    public string Description { get { return "什么时候该用它（模型据此判断）"; } }
    public string ParametersJson
    {
        get { return @"{ ""type"":""object"", ""properties"": { … }, ""required"": [ … ] }"; }
    }
    public Task<ToolResult> InvokeAsync(IDictionary<string, object> args, CancellationToken ct)
    {
        // …干活，返回 ToolResult.Success(输出) 或 ToolResult.Fail(错误)…
    }
}
```

2. 在 `src/Tools/ITool.cs` 的 `ToolRegistry.CreateDefault()` 里加一行：

```csharp
reg.Register(new YourTool());
```

**之后主 Agent 就能通过 function calling 调用它**，agent 循环、界面显示工具调用、
事件标签全都不用改。

#### 但子 Agent 拿不到 —— 除非你补第 3 步

工具集是分两路构建的：

```csharp
// 主 Agent：全部基础工具，不筛
foreach (var t in _baseTools.All) tools.Register(t);

// 子 Agent：按白名单筛
if (profile.Tools == null || profile.Tools.Length == 0)
    foreach (var t in _baseTools.All) tools.Register(t);   // 空白名单 = 全给
else
    foreach (var name in profile.Tools) { var t = _baseTools.Find(name); if (t != null) tools.Register(t); }
```

**内置的 9 个 agent 每一个都有显式白名单**，所以新工具对它们一律不可见。

3. **（可选，但通常需要）**把工具名加进要用它的 agent 的 `Tools` 数组：

```csharp
// src/Core/AgentProfile.cs，比如给「Web 漏洞」那个 agent
Tools = new[] { "http_request", "web_fetch", "payload", "your_tool" },
```

漏了这步**不会报错**，但 `build/tool_parity.ps1` 会提示：

```
已注册工具: 20 个
白名单出现: 19 个
[ OK ] 白名单里每个工具都已注册
[WARN] 有工具没有任何 agent 能用: your_tool
       （编排型 agent 不带工具是正常的；但如果这是解题工具就要补白名单）
```

**是 WARN 不是 FAIL** —— 因为「主 Agent 专用的工具」是合法情况（比如 `delegate`
就只在主 Agent 手里）。判断标准：**这工具是给谁用的？**

| 工具给谁用 | 要不要补白名单 |
|---|---|
| 主 Agent（编排、调度类）| 不用 |
| 某个方向的子 agent（解题类）| **要补** |

#### 验证过三次

| 轮次 | 怎么验的 | 结论 |
|---|---|---|
| 早期 | 加 `web_fetch` | 从 4 个工具变 5 个，两步够用（主 Agent 能用）|
| 225 | 照指南加一个临时页面 | 发现漏了 smoke 那步 |
| **226** | **照指南加一个临时工具** | **发现漏了「子 agent 白名单」那步** |

第 226 轮的做法：建一个 `TempProbeTool`、注册、跑 `tool_parity`：

```
已注册工具: 20 个  [base bin cipher … temp_probe_tool web_fetch web_search]
白名单出现: 19 个
[ OK ] 白名单里每个工具都已注册
[WARN] 有工具没有任何 agent 能用: temp_probe_tool
```

**没有 FAIL，只有一条 WARN。** 这说明「两步」在技术上够 —— 工具能注册、主 Agent 能用。
但**子 agent 永远用不到它**，而指南里一个字都没提。

## 加一个会话标签

会话页的标签（会话 / 事件 / 拓扑 / 文件 / Flag / 经验，**共 6 个**）不是 `IPage`，
是普通的 `Control` + 一个挂在 `Tag` 上的刷新委托。**两步。**

### 第一步：在 `SessionTabs.cs` 里写一个 `BuildXxx`

照现有四个的形态抄——它们的结构是固定的：

```csharp
public static Control BuildYours(Core.SessionStore store, string sessionId)
{
    var root = new Panel { Dock = DockStyle.Fill, BackColor = Theme.Bg,
                           Padding = new Padding(12, 10, 12, 10) };

    var grid = new DataTable { Dock = DockStyle.Fill };
    grid.AddColumn("seq",   "#",   0.4f, DataGridViewContentAlignment.MiddleRight);
    grid.AddColumn("text",  "内容", 5f);

    var hint = new Label
    {
        Dock = DockStyle.Bottom, Height = 24,
        ForeColor = Theme.Muted, Font = Theme.FontSmall,
        TextAlign = ContentAlignment.MiddleLeft,
    };

    root.Controls.Add(grid);
    root.Controls.Add(hint);

    Action refresh = delegate
    {
        var sf = store.Load(sessionId);
        var rows = new List<Dictionary<string, object>>();
        // …从 sf.Messages 推导 rows…
        grid.Fill(rows);
        hint.Text = rows.Count == 0 ? "空状态该说什么" : "共 " + rows.Count + " 条";
    };

    refresh();                      // 先刷一次，别让用户看到空表
    root.Tag = new Action(refresh); // ← 关键：标签切换时靠这个刷新
    return root;
}
```

**三个必须遵守的点**：

| 点 | 为什么 |
|---|---|
| `root.Tag = new Action(refresh)` | `SessionView` 切标签时读 `Tag as Action` 调它。不设就永远不刷新。|
| 先 `refresh()` 再返回 | 不先刷一次，用户第一次点进来看到的是空表。|
| 一定要写 `hint` 的空状态文案 | 空表 + 没有提示 = 用户以为程序坏了。|

### 第二步：在 `SessionView.CreateView` 里挂上去

```csharp
var yourTab = new TabPage("你的标签") { BackColor = Theme.Bg, Padding = new Padding(0) };
yourTab.Controls.Add(SessionTabs.BuildYours(_store, _sessionId));
tabs.TabPages.Add(yourTab);
```

**就这两步**，`tabs.SelectedIndexChanged` 那段是通用的，会自动找到新标签的
`Tag` 并刷新，不用改。

> 实测：加「拓扑」标签总共改了约 70 行（60 行 `BuildTopology` + 4 行挂载 + 注释），
> 没动任何别的文件。

#### 这一节为什么没有「第三步」

对比一下：**加页面要改 5 处、加工具要改 2-3 处，加会话标签只要 2 处。**

差别在**有没有外部清单要对齐**：

| 加什么 | 要同步的清单 | 漏了会怎样 |
|---|---|---|
| **页面** | `PageIcons.Map`、`smoke.ps1`、`clip/layout/overflow` 三份 `$pages` | `tool_parity` 报 FAIL |
| **工具** | 各 agent 的 `Tools` 白名单 | `tool_parity` 报 WARN |
| **会话标签** | **没有** | — |

会话标签是纯内部的：`SessionTabs.BuildXxx` + `tabs.TabPages.Add(...)`，
刷新走通用的 `SelectedIndexChanged`（读 `Tag` 上的 `Action`），
**没有任何地方需要登记它的存在**。

> 所以「加 X 要几步」这个问题，答案取决于 **X 有没有出现在别的地方**。
> 加页面/加工具之所以步骤多，是因为页面和工具都在多个清单里被引用。
>
> **唯一会过期的文档是 `界面清单.md` 第 2 节那几个标签名**（不检查，但应该改）。

## 加一个自绘控件

当系统控件的配色跟不上深色主题时（`CheckBox` 白底方块、`ComboBox` 白下拉），
写一个自绘控件比改系统控件便宜。**新建一个文件，用完 `new` 一下就行**，不改任何注册表。

### 骨架

```csharp
public sealed class YourWidget : Control        // 或 Panel / Button 子类
{
    public YourWidget()
    {
        SetStyle(ControlStyles.AllPaintingInWmPaint
               | ControlStyles.OptimizedDoubleBuffer
               | ControlStyles.UserPaint
               | ControlStyles.ResizeRedraw, true);
        DoubleBuffered = true;
        BackColor = Theme.Surface;
        ForeColor = Theme.Text;
    }

    protected override void OnPaint(PaintEventArgs e)
    {
        var g = e.Graphics;
        g.SmoothingMode = SmoothingMode.AntiAlias;
        g.TextRenderingHint = System.Drawing.Text.TextRenderingHint.ClearTypeGridFit;

        // 1. 先把底色铺回来（自绘会盖掉默认背景）
        using (var bg = new SolidBrush(BackColor))
            g.FillRectangle(bg, ClientRectangle);

        // 2. 尺寸太小时直接返回，别画
        if (Width < 30 || Height < 20) return;

        // 3. 用 Theme 的工具画
        //    using (var path = Theme.RoundPath(rect, Theme.RadiusMd)) …
        //    Theme.DrawShadow(g, rect, radius, spread, alpha)
        //    Theme.Mix(a, b, weight)  ← color-mix(in srgb, a W%, b) 的等价物
    }
}
```

### 四个必须记住的坑

| 坑 | 后果 | 办法 |
|---|---|---|
| 不铺底色 | 控件区域会残留上一帧的像素，拖动窗口时花屏 | `OnPaint` 第一件事就是 `FillRectangle(BackColor)` |
| 不设 `DoubleBuffered` | 重绘闪烁 | 构造里 `SetStyle(...OptimizedDoubleBuffer)` + `DoubleBuffered = true` |
| 不自适应尺寸 | 窗口缩小时画出界 | `OnPaint` 开头判 `Width/Height` 下限，不够直接 return |
| **重绘里做测量** | 每次重绘都重算一遍文字尺寸 | **构造时量好存字段，`OnPaint` 只读**（`ChatBubble._blockSizes` 就是这么改的，重绘快 39%）|

### 现有可复用的绘制件

| 方法 | 用途 |
|---|---|
| `Theme.RoundPath(rect, radius)` | 统一圆角；`Theme.RadiusPill` 是胶囊 |
| `Theme.RoundPathCorners(rect, tl, tr, br, bl)` | 四角不同半径（聊天气泡的说话人侧收小）|
| `Theme.DrawShadow(g, rect, radius, spread, alpha)` | 柔和投影 |
| `Theme.Mix(a, b, weight)` | 混色（对应 CSS `color-mix`）|
| `Theme.AgentColor(i)` | 8 个 agent 标识色 |

### 两个现成的例子

- **`Widgets/Switch.cs`** —— 继承 `CheckBox`，只换画法。调用方 `new CheckBox` 改成
  `new Switch` 即可，`Checked` / `Text` / `Click` 全部照旧。
  （注意覆盖 `GetPreferredSize`，否则 `AutoSize = true` 会算错宽度。）
- **`Widgets/Sparkline.cs`** —— 从 `Control` 起手画折线，演示「空数据画提示而不是空折线」。

## 删功能

| 删什么 | 怎么做 |
|---|---|
| **删页面** | 删文件 + 删 `Program.RegisterPages()` 里那一行 |
| **删工具** | 删文件 + 删 `ToolRegistry.CreateDefault()` 里那一行 + 从各 agent 白名单里去掉名字 |
| **删 agent** | 删 `AgentLibrary.Default()` 里那一项 |
| **删设置项** | 删 `AppConfig` 字段 + 设置页那两个控件 + `SavePrefs` 里的赋值 |

**没有任何地方硬编码了页面名、工具名、agent 名**——所以删掉之后不会有残留引用。

### 实测：删掉「通知」页

为了验证这套流程，我实际删了一次（在临时副本上，不动交付物）：

| 步骤 | 改动 |
|---|---|
| 1. 删文件 | `src/Ui/Pages/NotifyPage.cs`（297 行） |
| 2. 删注册 | `Program.cs` 一行（`PageRegistry.Register(new Pages.NotifyPage())`） |
| 3. 删关联调用 | `Program.cs` 一行（`Pages.NotifyCenter.Shutdown()`，那个类就定义在被删的文件里） |
| 4. 同步冒烟脚本 | `build/smoke.ps1` 去掉 notify 检查项 |

**结果**：

```
编译：49 个文件 → 1656 KB（原来 50 个 / 1662 KB）  ✅
冒烟：12 / 12 通过（原来 13 页）                    ✅
侧栏：「通知」消失                                  ✅
残留引用：0                                         ✅
```

**总共 3 处改动，一次编译通过，无残留。**

> 第 3 步是容易漏的：`NotifyCenter` 这个静态类定义在 `NotifyPage.cs` 里，删文件会连带删掉它，而 `Program.cs` 退出时调了 `NotifyCenter.Shutdown()`（清托盘图标）。
> 编译器会直接报出来，不会静默漏掉。但如果删的是别的东西（比如只被反射调用的），就得自己查一遍引用。

## 接入一个 MCP 服务器

在「MCP 接入」页点「+ 添加服务器」：

| 字段 | 说明 |
|---|---|
| 名称 | 工具会以 `<名称>_<工具名>` 的形式暴露给模型 |
| 传输 | 目前长连接支持 `stdio`；`http`/`sse` 能配能测，但还不能接入 agent |
| 命令 | 可执行文件绝对路径（如 `C:\Python311\python.exe`） |
| 参数 | 空格分隔 |
| **环境变量** | 每行一个 `KEY=VALUE` |
| 超时 | 秒 |

**环境变量这一步最容易漏**。很多 Python 写的 MCP 服务器需要 `PYTHONPATH`
才能 import 到自己的模块；不给的话进程起来就退出，表现是「测试连接失败」。

配好之后保存，开关拨到「启用」，然后**重新进一次会话**——MCP 装配是在会话
构建时做的。接入成功会在聊天区出现一行「已接入 N 个 MCP 服务器（M 个工具可用）」。

## 加一条自己的技能

**不用改代码、不用重编译**。打开「技能」页，点「+ 新建技能」：

| 字段 | 说明 |
|---|---|
| 技能 ID | 短英文标识，如 `my-sqli-trick`。**与内置同名会覆盖它** |
| 领域 | `web` / `reverse` / `ctf` / 任意 |
| 一句话说明 | 检索时显示这行，写清楚「什么场景用」 |
| 正文 | Markdown，写手法、判读信号、容易踩的坑 |

存进 `%APPDATA%\SpiritScout\my-skills.json`，**升级 exe 不会丢**。

**写完立刻生效**：`kb_search` 工具和技能页读的是同一份合并结果，agent 下次
解题时检索「关键词」就能命中你刚写的那条。

也可以「导入」一个 `skills.json` 格式的文件批量加。
「导出用户技能」把自有的一批导出来备份或分享。

> 内置的 288 条不能删（只读）。想改某条的行为，新建一条同 id 的覆盖它。
